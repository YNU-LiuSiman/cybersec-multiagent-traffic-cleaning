# 答辩 Q&A 备忘录（硬核反问标准应答）

> 覆盖计划书预备 5 大核心问题 + 3 个实验结果衍生深度追问，所有数字均与 `course_project/results/` 严格一致。

### Q1：“这不就是写一堆 Python 规则工具，外面套了个 LLM 壳吗？”
**标准应答**：
我们专门设置了**核心对照 `Static-Pipeline`**——它调用的 Python 工具与我们完全一模一样，只是把 LLM 换成了固定顺序 + 固定阈值规则。在 10 个随机盲测场景上，结果呈现决定性分野：
- **`Static-Pipeline` 惨败**：整表漂移阈值无法区分 Node D 合法的 19× Non-IID 分布差异与真单位故障，在 10/10 场景上对 Node D 触发了总计 **100 次误处置**，直接把 Rare-4 在官方测试集上的 RF 召回打成 **`0.0000`**（RF Macro-F1 跌至 `0.4158`），且无语义能力导致残余别名准确率 **`0.00`**；
- **`Ours (Full)` 显著胜出**：RF 达 **`0.5173`**（`+0.1016`, `p_holm=0.0068`），HistGB 达 **`0.4700`**（`+0.0569`, `p_holm=0.0068`），控制面全项 `10/10` 满分且 Node D 零误处置；
- 在零改动迁移的 CICIDS-2017 上，同工具的 `Static-Pipeline` 把 71.4%（5/7）的突发/跨天干净分片误报为故障，而 LLM 控制面综合 Benign 锚点、物理守恒与自置信度做到 **`0.0% FPR (0/7)`**。这证明价值不在“工具”，而在 LLM 控制面的跨证据语义归因。

### Q2：“你们提示词里是不是偷偷写了列名、因子或者节点故障，相当于背答案？”
**标准应答**：
我们用三道硬机制彻底杜绝作弊：
1. **自动化防泄漏审计（`tests/test_prompt_leak.py`）**：CI 级正则扫描 `node_agent.md` 与 `coordinator_agent.md`，禁止出现任何 UNSW/CIC 列名、具体漂移倍率（1000/1024/0.125）、节点编号、阈值数字、攻击类名与数据集名，测试 **2/2 PASSED**；
2. **全随机化场景 + 开发/评测种子隔离**：每个场景随机打乱节点角色映射、随机抽取作弊列名（10 个候选池）与残余语义别名（12 列词库），提示词仅在 `seed 0–2` 上打磨后即冻结并记录 SHA256 哈希，再一次性跑 `seed 100–109` 盲测集；
3. **跨数据集零改动铁证**：同一套冻结提示词一个字不改直接跑 CICIDS-2017，同样实现 `0% FPR / 100% TPR`，靠“背 UNSW 答案”绝不可能做到。

### Q3：“为什么不在样本级做多智能体跨节点投票或联邦去噪？”
**标准应答**：
我们在前期 Phase 4/5 专门做过红队验证：跨节点交换 K-means 类原型互投（`Ours_MAS_v3`）在 UNSW-NB15 5 节点 Non-IID 上 RF Macro-F1 为 **`0.4635`**，反而**显著低于零通信本地稀缺豁免去噪 `B6`（`0.4751`，`p = 0.0044`）**。原因是极端 Non-IID 下外节点从未见过某稀有类，容易给出错误反对票。因此我们尊重负结果，把架构定位于**“样本去噪留本地，跨节点协作在控制面”**——跨节点只传统计摘要，解决单节点根本看不见的跨节点捷径、量纲统一与全局稀缺计数。

### Q4（深度追问）：“主表里 `Ours w/o Coordinator` 的 RF Macro-F1 (`0.5269`) 甚至比你们完整版 (`0.5173`) 和 `Oracle-Clean` (`0.5185`) 还高，怎么解释？”
**标准应答**（最能拉满学术印象分的一题！）：
这是一个非常经典的**不平衡指标统计悖论**，也是我们坚持设立“控制面指标 + Oracle 上界”的原因。拆开 `Ours w/o Coordinator` 的控制面成绩可以看到它其实**全面崩盘**：单位漂移恢复 `0.00`、残余别名 `0.00`、噪声节点检出仅 `0.10` 且误报 `7` 次、脏行修复 `0.00`、误伤 Node D `5` 次（Rare-4 留存掉到 `94.4%`）。但它为什么在 RF 上反而超过完美真值上界 `Oracle-Clean`？因为 Role B 上约 2.4 万条多数类攻击样本的 `1000×/1024×` 漂移没有被修复，它们被推离了测试集的正常特征区间，**意外起到了“多数类降采样”的效果**，从而把极少类 `Worms` 的召回硬生生拉高了（RF Rare-4 召回从 Oracle 的 `0.2256` 虚高到 `0.2966`）。这恰恰说明：不能只靠单一 Macro-F1 评判数据治理系统，必须同时看控制面是否真正修对了故障以及是否逼近 `Oracle-Clean` 真实数据分布。

### Q5（深度追问）：“干净对照 `seed 200–202` 上你们为什么 `clean_control_fpr` 不是 0？”
**标准应答**：
我们 100% 如实披露这一发现：在 3 个完全不注入任何故障的干净对照场景上，`Ours (Full)` 对所有 Schema、量纲漂移、脏行和作弊列都做到了 **0 误报**；唯一的误触发发生在 `local_cl_clean`——当全网没有任何真正高噪节点作为参照时，Node D 因包含全部 10 个类别且样本量只有 peers 的 1/3（8.7k vs 24k），其本地 10 分类 CV 的自然模糊度（`suspected_noise_rate ≈ 0.110`）高于 6 分类 peers（`0.043`），触发了相对比较敏感。但有两点非常关键：**① 因为 Coordinator 携带了全局 `Rare-Exempt` 豁免，Node D 的 1,682 条 Rare-4 实现 100.0% 零损失保留**；② 下游 RF Macro-F1 保持 `0.4950–0.5043`，与 Oracle (`0.4977–0.4995`) 几乎无损（而 `Static-Pipeline` 在干净对照上掉到 `0.4024`）。未来只需在 `tools_node` 中按类别数/熵做基线校准即可根治。

### Q6：“模拟多节点切分是不是太理想化，和真实生产环境有差距？”
**标准应答**：
我们诚实声明模拟边界：UNSW-NB15 4 节点故障是可控合成注入，目的是在拥有精确 Ground Truth 的前提下严格度量控制面 P/R 与统计显著性；同时我们补充了 **CICIDS-2017 真实时间切片（自然 DDoS 0.06%→77.4% + 跨天周二 Benign）** 与 **CICIDS-2018 真实脏数据（idx=413 重复表头 + 349 Inf）** 两个真实数据验证，证明方法在真实时序突变与跨版本脏数据上同样有效。

### Q7：“LLM 输出不稳定怎么办？生产里 136 秒、6 万多 token 实用吗？”
**标准应答**：
稳定性方面：我们采用 `temperature = 0`、严格 Executor Schema 校验 + 最多 2 次自动重试，且所有数据修改由确定性 Python 执行。在 3 个盲测场景 × 3 次重复实测中，**8/9 次（88.9%）实现全部故障 100% 精确一致**，仅 1 次因跳过追问轮漏检 1 项（未来在编排层强制至少 1 轮 CL 追问即可消除）。成本方面：多源 IDS 训练集体检属于**模型重训前的离线批处理环节**（按天/按周执行），单次约 2 分钟与几分钱级 Flash 模型 API 费用完全可接受，远低于人工排查跨探针静默数据损坏的人力成本。
